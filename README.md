# CareerVerse Backend — Architecture & State Report (MVP)

Этот документ описывает текущее состояние бэкенд-части проекта CareerVerse, разработанной на стеке **NestJS, Prisma, PostgreSQL и Supabase**. Он служит финальной документацией MVP и описывает ключевые архитектурные решения.

---

## 1. Data Model & Schema

В основе системы лежат 4 ключевые сущности, управляемые через `schema.prisma`.

### Таблицы:
- **`User`**: Содержит основную информацию о пользователе (`id`, `email`, `xp`, `coins`, `level`).
- **`Profession`**: Описывает направление развития (например, "Backend Developer"). Содержит `id`, `title`, `description`.
- **`Level`**: Конкретный шаг/задача внутри профессии. Имеет связь с `Profession` (`professionId`). Содержит `order`, `rewardXp`, `rewardCoins` и JSON-поле `taskData` для гибких настроей заданий.
- **`UserProgress`**: Связующая таблица (Many-to-Many), фиксирующая факт прохождения уровня пользователем. Имеет поля `isCompleted` и дату прохождения.

### Индексы и Оптимизации:
- В `UserProgress` внедрен составной уникальный индекс `@@unique([userId, levelId])`. Он гарантирует на уровне базы данных, что пользователь не сможет создать две записи о прохождении одного и того же уровня.
- Наличие правильных внешних ключей `REFERENCES` с каскадным поведением (по умолчанию).

## 2. Business Logic & Security

### Защита от Race Condition (Interactive Transactions)
Механизм завершения уровня (`ProgressService.completeLevel`) является критическим узлом бизнес-логики, так как он начисляет игровую валюту.
Для защиты от атаки **TOCTOU** (Time-of-Check to Time-of-Use), когда параллельные запросы могут привести к двойному начислению опыта, реализована интерактивная транзакция Prisma (`$transaction`):
1. Внутри транзакции проверяется существование прогресса.
2. Происходит создание `UserProgress`.
3. Атомарно инкрементируются поля `xp` и `coins` у `User`.
Если любая из операций падает, происходит полный откат (Rollback).

### Система прогрессии и блокировки (isLocked)
Метод `UsersService.getDashboardData` агрегирует статистику для дашборда:
- Использован **единый оптимизированный запрос Prisma** с `include` и агрегацией `_count`, что полностью устраняет проблему N+1 запросов.
- Подтягиваются только те записи `progress`, которые принадлежат конкретному пользователю и имеют флаг `isCompleted: true`.
- Логика блокировки (`isLocked`) вычисляется на сервере: профессия доступна по умолчанию, если она первая в списке, либо если в предыдущей профессии пройден хотя бы 1 уровень.

### Механизм авторизации (Supabase JWT)
Авторизация интегрирована с Supabase.
- Создана кастомная `SupabaseStrategy` для `Passport.js`.
- Стратегия извлекает токен из заголовка `Authorization: Bearer <token>`, валидирует его криптографическую подпись с помощью `SUPABASE_JWT_SECRET` и извлекает `user_id` из поля `sub`.
- Эндпоинты защищаются глобально или точечно с помощью `JwtAuthGuard` (`@UseGuards(JwtAuthGuard)`).

## 3. API Infrastructure

### Ключевые эндпоинты:
1. **`GET /api/users/:id/dashboard`**
   - Возвращает агрегированную информацию о профессиях (totalLevels, completedLevels, isLocked).
2. **`GET /api/users/:id/stats`**
   - Возвращает общую статистику профиля (опыт, монеты, полностью завершенные профессии). Использован класс `Set` для поиска за $O(1)$ при проверке завершения профессии.
3. **`POST /api/progress/complete`**
   - Эндпоинт начисления наград. Принимает `CompleteLevelDto`.

### Валидация DTO
Реализован строгий **ValidationPipe** на глобальном уровне `main.ts` (`whitelist: true`, `forbidNonWhitelisted: true`). Он блокирует запросы с невалидными UUID или атаки типа *Mass Assignment* (попытка передать "hackerField" в Payload).

### Обработка ошибок (PrismaExceptionFilter)
Создан и подключен глобальный фильтр `PrismaExceptionFilter`. Он перехватывает низкоуровневые ошибки базы данных (PrismaClientKnownRequestError) и преобразует их в корректные HTTP-статусы:
- `P2002` (Unique constraint failed) -> `409 Conflict`.
- `P2025` (Record not found) -> `404 Not Found`.

## 4. Testing & Stability

- **Unit Tests**: Созданы полные изолированные тесты для `ProgressService` и `UsersService`. PrismaService полностью замокан (Mock), тестируются все граничные сценарии (выброс исключений, корректность фильтрации).
- **E2E Tests**: Написан комплексный набор E2E тестов для эндпоинта прогрессии с помощью `Supertest`. Проверяется структура JSON-ответов, коды статусов (200, 400, 404, 409) и работа валидаторов `class-validator`.
- **Seed Script (`prisma/seed.ts`)**: Создан идемпотентный скрипт для наполнения базы первичными данными (2 профессии по 5 уровней). Использование статических UUID и механизма `upsert` позволяет безопасно вызывать команду `npx prisma db seed` при деплое.

---

## 5. Deployment Readiness (Интеграция с Flutter)

Проект полностью готов к деплою и стыковке с фронтендом:
1. **CORS**: Разрешен в `main.ts`, что позволяет Flutter Web/App беспрепятственно выполнять запросы к API.
2. **Swagger Documentation**: Настроена интерактивная документация по пути `/api/docs`. Все методы и DTO аннотированы (`@ApiProperty`, `@ApiResponse`), включая примеры возвращаемых JSON.
3. **Environment Management**: База данных подключается через `DATABASE_URL`, аутентификация зависит от `SUPABASE_JWT_SECRET`. Проект готов к запуску в Docker или на платформах вроде Render/Railway.
