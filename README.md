# CareerVerse

**Профориентация для школьников Казахстана — разговор вместо теста с вариантами ответов.**

Подросток отвечает своими словами, а не выбирает из четырёх пунктов. Следующий
вопрос рождается из предыдущего ответа, и никто заранее не знает, сколько их
будет: разговор кончается, когда становится понятно, что человеку подходит и
почему. На выходе — профессии из каталога на 102 позиции, зарплаты и спрос по РК,
путь к первой работе, рабочая проба и письмо родителям.

## Проблема

Школьные профориентационные тесты работают по ключу ответов. Ученик выбирает
вариант из списка, сумма баллов попадает в заранее написанный текст, и на выходе
получается «тип личности», из которого непонятно, что делать в понедельник.
Вопросы одинаковы для восьмиклассника и для выпускника перед ЕНТ. Казахоязычный
школьник читает всё это по-русски.

CareerVerse построен наоборот: **ключа ответов нет вообще**. Убрать модель —
останется пустой экран.

## Как проходит тест

1. **Согласие и класс.** Экран согласия (требование закона РК № 230-VIII) и
   вопрос «в каком ты классе» — восьмикласснику и выпускнику нужны разные примеры
   и разная сложность. Полей о себе — ноль: ни имени, ни почты, ни телефона.
2. **Вопрос «кем ты сейчас думаешь стать».** Ответ **намеренно не уходит на
   сервер** и живёт в `localStorage`: попади он в диалог — приехал бы в промпт
   подбора вместе с ответами, и модель просто подтвердила бы названную профессию.
3. **От 4 до 10 вопросов свободной речью.** Каждый следующий строится на
   предыдущем ответе. Профиль интересов растёт полосами прямо на экране.
4. **Результат.** Подобранные профессии с объяснением выбора, данные рынка труда
   РК и блок «ожидание против результата»: что подросток думал сам — и что
   получилось. Четыре исхода: совпало, почти совпало, разошлось, «было не знаю».
5. **Дальше по желанию** — рабочая проба из двух шагов, путь в профессию (ЕНТ,
   вузы, английский, первая работа), письмо родителям потоком, аккаунт с
   историей прохождений и разбор от наставника за очки.

## Что здесь сделано не как обычно

**Отписками тест не пройти.** «Не знаю», «норм», «ааа» модель помечает
`informative: false`, объясняет, чего не хватило, и задаёт тот же вопрос заново —
проще и конкретнее, до двух раз подряд. Пустые ответы не двигают счётчик
содержательных, поэтому проскочить до результата, ничего не сказав, нельзя.

**Длину разговора решает не счётчик.** Тест заканчивается тогда, когда модель
говорит, что уже может назвать профессии и объяснить выбор. Уверенность профиля
тоже называет она, а не арифметика по числу ходов.

**Рабочая проба вынесена из теста и стала добровольной.** Подбор всегда шёл по
диалогу, поэтому результат честен и без пробы. Кнопка появляется на экране
результата — когда человек уже знает, что ему подобрали, и решает, хочет ли
попробовать эту работу руками. Второй шаг пробы вырастает из принятого решения в
первом.

**Каталог — 102 профессии.** Модель отвечает только из каталога, поэтому его
длина и была потолком теста: шесть направлений — шесть возможных ответов, как бы
глубоко ни раскрылся человек. Сейчас это право, финансы, IT, инженерия, медицина,
образование, медиа, наука, транспорт, сервис — и отдельно десять профессий, куда
идут через колледж, а не через вуз. Идентификаторы короткие и читаемые
(`lawyer`, `chef`), чтобы модель не промахнулась по 36 символам UUID.

**О чём данных нет — сказано прямо.** Медианы зарплат с hh.kz есть у 18
профессий. Подставлять остальным среднее по отрасли пробовали и отказались: у
всех айтишников выходила одна цифра, у всех медиков другая, и на экране это
читалось как данные о профессии, хотя было данными об отрасли. Экран результата
про отсутствие цифр говорит открыто.

**Аккаунт без почты и пароля.** Контакты подростков 14–17 лет мы не собираем:
аккаунт — это имя, класс и город, а вместо пароля выдаётся код входа вида
`K7WF-3RTM` (алфавит без похожих символов: ни `0`/`O`, ни `1`/`I`). Тест
проходится анонимно, аккаунт предлагается после результата, и прохождение
привязывается задним числом.

## Соответствие закону РК № 230-VIII

Закон об искусственном интеллекте действует с 18 января 2026 года. Реализовано:

- экран согласия перед началом с фиксацией момента (`Session.consentAcceptedAt`);
- дисклеймер о том, что рекомендации даёт ИИ и решение остаётся за человеком;
- **маркировка сгенерированного контента**: каждое задание хранит `modelId`
  использованной модели, API отдаёт флаг `generatedByAi`, интерфейс показывает
  бейдж (`web/app/components/AiBadge.tsx`);
- данные несовершеннолетних не собираются: ни почты, ни телефона, ни геолокации.

## Архитектура

```
Браузер — Next.js 16 · React 19 · Tailwind 4        (Vercel)
     │
     │  fetch + SSE (письмо родителям идёт потоком)
     ▼
API — NestJS 11 · Prisma 7                          (Vercel Functions, Frankfurt)
     │
     ├── src/sessions      сценарий прохождения целиком
     ├── src/ai            клиент модели и девять промптов
     ├── src/auth          вход по коду, глобальный JWT-guard
     ├── src/professions   каталог и рынок труда РК
     └── src/progress      очки, уровни, награды
     │
     ├──► Claude API       structured outputs через zod
     └──► PostgreSQL       Supabase, Frankfurt — рядом с функцией
```

Бэкенд и фронт — две независимые сборки со своими `package.json` и своими
проектами на Vercel. Общего workspace нет намеренно: деревья зависимостей и
версии TypeScript у них разные. База и функция стоят в одном регионе — тёплый
запрос с обращением к базе укладывается в ~0.3 с.

### Слой ИИ

`src/ai` — девять промптов: разбор свободного ответа, следующий вопрос,
переспрос, подбор профессий, рабочая проба, её второй шаг, письмо родителям,
разбор наставника и путь в профессию. Все структурированные ответы идут через
structured outputs + zod-схемы (`src/ai/schemas.ts`), поэтому парсинга текста
руками нигде нет.

**Модель зависит от языка.** Русский — `claude-haiku-4-5`, казахский —
`claude-sonnet-5`: на Haiku казахский получается ломаным, это проверено прогоном.
Обе модели задаются переменными окружения, так что переключение — одна строка в
`.env`. Расход пишется в лог на каждом вызове; полное прохождение стоит около
$0.06 на русском и $0.12 на казахском.

## Безопасность

- **Закрыто по умолчанию.** `JwtAuthGuard` подключён глобально через `APP_GUARD`,
  публичность объявляется явным `@Public()`. `userId` берётся из токена и никогда
  из URL или тела запроса — роуты вида `/users/:id/*` заменены на `/users/me/*`.
- **Начисление наград защищено от гонки.** `@@unique([userId, levelId])` плюс
  интерактивная транзакция Prisma: проверка, создание прогресса и инкремент
  `xp`/`coins` происходят атомарно. Проверено на живом сервере — восемь
  параллельных запросов дают один успех, семь `409` и 200 XP вместо 1400.
- **Строгая валидация.** Глобальный `ValidationPipe` с `whitelist: true` и
  `forbidNonWhitelisted: true` отбивает невалидные UUID и mass assignment.
- **Ошибки базы не текут наружу.** `PrismaExceptionFilter` превращает `P2002` в
  `409 Conflict`, `P2025` — в `404 Not Found`.
- **Без переменных окружения приложение не стартует.** `DATABASE_URL`,
  `SUPABASE_JWT_SECRET` и `ANTHROPIC_API_KEY` обязательны — падение на старте
  лучше, чем тихая работа с дефолтом.

## Модель данных

Схема делится на справочник и прохождение.

| Сущность | Роль |
|---|---|
| `User` | Имя, класс, город, код входа. Почты и пароля нет. Плюс `xp`, `coins`, `level` |
| `Profession` · `LaborMarketData` | Каталог направлений и цифры рынка труда РК |
| `Session` | Одно прохождение: язык, класс, статус, согласие, момент привязки к аккаунту. `userId` nullable — тест идёт без логина |
| `TaskInstance` | Конкретное задание, сгенерированное под этого человека. Хранит `modelId` |
| `Answer` · `Assessment` | Свободный ответ и его разбор: содержателен ли, хватает ли данных для подбора, насколько модель уверена |
| `InterestProfile` | Накопленные сигналы интересов и подобранные профессии |
| `ParentLetter` · `MentorReview` · `CareerPlan` | Артефакты, каждый по одному на прохождение — чтобы не платить за повторную генерацию |

Ключевые ограничения: `@@unique([userId, levelId])` — замок против двойного
начисления; `@@unique([sessionId, order])` — два задания не встанут на одно
место; `sessionId` уникален у каждого артефакта; `User.loginCode` уникален.

## Запуск локально

Нужны Node.js 20+, PostgreSQL и ключ Anthropic API.

```sh
# 1. Переменные окружения
cp .env.example .env          # заполнить DATABASE_URL, SUPABASE_JWT_SECRET, ANTHROPIC_API_KEY

# 2. База
npx prisma migrate deploy
npx prisma db seed            # идемпотентно, можно вызывать повторно

# 3. Бэкенд, порт 3000
npm install && npm run build && npm run start:prod

# 4. Фронт, порт 3001
cd web && npm install && npm run dev
```

Открыть `http://localhost:3001`, Swagger — `http://localhost:3000/api/docs`.

## Тесты

```sh
npm test          # 14 unit: ProgressService и UsersService с замоканной Prisma
npm run test:e2e  # 10 e2e: эндпоинт прогрессии через Supertest
```

Покрыты граничные сценарии начисления и валидация. Адаптивный разговор,
переспрос, потолок вопросов и списание очков проверялись прогонами на живой
модели, а не тестами.

## Деплой

```sh
vercel deploy --prod --yes            # бэкенд, из корня
cd web && vercel deploy --prod --yes  # фронт
```

Каталог профессий живёт в базе, а не в коде, поэтому деплой его не обновляет.
SQL генерируется из `prisma/catalog.ts`, чтобы описания в коде и в базе не
разъезжались:

```sh
npm run catalog:sql   # получить SQL и применить его к базе
```
