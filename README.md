# CareerVerse — устройство проекта

Репозиторий целиком: бэкенд на **NestJS + Prisma + PostgreSQL** в корне и фронт на
**Next.js** в [web/](web). Что сделано, что осталось, риски к защите и инструкции по
деплою — в [PLAN.md](PLAN.md); этот файл описывает, как всё устроено внутри.

## 1. Data Model & Schema

Схема делится на две части: справочник профессий и прохождение теста.

### Пользователь и справочник
- **`User`**: `name`, `grade`, `city`, `loginCode` — почты и пароля нет намеренно,
  подросткам 14-17 лет мы их не задаём. Плюс игровые `xp`, `coins`, `level`.
  Поле `email` осталось nullable для совместимости и не используется.
- **`Profession`**: направление (`title`, `titleKk`, `description`, `order`).
- **`LaborMarketData`**: зарплаты, вакансии и спрос по РК для экрана результата.
- **`Level`** / **`UserProgress`**: наследие первой версии — шаблоны уровней и
  факт их прохождения. В адаптивном тесте не участвуют.

### Прохождение теста
- **`Session`**: одно прохождение. `locale`, `grade`, `status`,
  `consentAcceptedAt` (закон РК № 230-VIII), `claimedAt` — момент привязки к
  аккаунту. `userId` nullable: тест проходится без логина.
- **`TaskInstance`**: конкретное задание, сгенерированное под этого человека —
  уточняющий вопрос или шаг рабочей пробы. Хранит `modelId` (маркировка ИИ).
- **`Answer`** / **`Assessment`**: свободный ответ и разбор его моделью. В
  `Assessment.scores` лежит вердикт: содержателен ли ответ, хватает ли данных для
  подбора, насколько модель уверена.
- **`InterestProfile`**: накопленные сигналы интересов и подобранные профессии.
- **`ParentLetter`**, **`MentorReview`**, **`CareerPlan`**: письмо родителям,
  платный разбор пробы и путь в профессию. Каждый — отдельный артефакт, чтобы не
  платить за повторную генерацию.

### Индексы и ограничения
- `UserProgress`: `@@unique([userId, levelId])` — замок против двойного начисления.
- `TaskInstance`: `@@unique([sessionId, order])` — два задания не встанут на одно место.
- `MentorReview`, `CareerPlan`, `ParentLetter`, `InterestProfile`: `sessionId` уникален,
  то есть на прохождение приходится ровно один такой артефакт.
- `User.loginCode` уникален — по нему происходит вход.

## 2. Business Logic & Security

### Защита от Race Condition (Interactive Transactions)
Механизм завершения уровня (`ProgressService.completeLevel`) является критическим узлом бизнес-логики, так как он начисляет игровую валюту.
Для защиты от атаки **TOCTOU** (Time-of-Check to Time-of-Use), когда параллельные запросы могут привести к двойному начислению опыта, реализована интерактивная транзакция Prisma (`$transaction`):
1. Внутри транзакции проверяется существование прогресса.
2. Происходит создание `UserProgress`.
3. Атомарно инкрементируются поля `xp` и `coins` у `User`.
Если любая из операций падает, происходит полный откат (Rollback).

### Система прогрессии и блокировки (isLocked)
Метод `UsersService.getDashboardData` агрегирует статистику для дашборда:
- Использован **единый оптимизированный запрос Prisma** с `include` и агрегацией `_count`, что полностью устраняет проблему N+1 запросов.
- Подтягиваются только те записи `progress`, которые принадлежат конкретному пользователю и имеют флаг `isCompleted: true`.
- Логика блокировки (`isLocked`) вычисляется на сервере: профессия доступна по умолчанию, если она первая в списке, либо если в предыдущей профессии пройден хотя бы 1 уровень.

### Регистрация и вход без почты и пароля
Собирать контакты подростков 14-17 лет мы не хотим, поэтому аккаунт — это имя,
класс и город, а вместо пароля выдаётся код входа вида `K7WF-3RTM`
(алфавит без похожих символов: ни `0`/`O`, ни `1`/`I`).

- `POST /api/auth/register` создаёт пользователя и возвращает токен и код.
- `POST /api/auth/login` меняет код на токен; код нормализуется, так что
  строчные буквы и потерянный дефис не мешают.
- Токен подписывается тем же `SUPABASE_JWT_SECRET`, которым `SupabaseStrategy`
  проверяет подпись, — поэтому весь существующий контур авторизации работает
  без правок. Supabase Auth при этом **не используется**: секрет здесь просто
  случайная строка. Если понадобится настоящий вход через Supabase, стратегию
  придётся переписать на JWKS/ES256.
- `JwtAuthGuard` глобальный (`APP_GUARD`): закрыто по умолчанию, открыто только
  явным `@Public()`. `userId` берётся из токена, никогда из URL или тела.

## 3. API Infrastructure

Полный список с примерами — в Swagger: `/api/docs`. Главное:

| Метод | Путь | Токен | Что делает |
|---|---|---|---|
| `POST` | `/api/sessions` | — | Начать прохождение, вернуть первый вопрос |
| `POST` | `/api/sessions/:id/answers` | — | Свободный ответ → следующий шаг или результат |
| `GET` | `/api/sessions/:id/result` | — | Профессии, рынок труда РК, состояние пробы |
| `POST` | `/api/sessions/:id/trial` | — | Начать рабочую пробу (по желанию, с экрана результата) |
| `POST` | `/api/sessions/:id/plan` | — | ЕНТ, вузы, английский, путь к первой работе |
| `GET` | `/api/sessions/:id/parent-letter` | — | Письмо родителям потоком (SSE) |
| `POST` | `/api/sessions/:id/claim` | ✅ | Привязать прохождение к аккаунту и начислить очки |
| `POST` | `/api/sessions/:id/mentor-review` | ✅ | Разбор пробы за очки |
| `POST` | `/api/auth/register` · `/login` | — | Аккаунт по имени и классу, вход по коду |
| `GET` | `/api/auth/me` | ✅ | Профиль и история прохождений |
| `GET` | `/api/professions` | — | Каталог с данными рынка труда |
| `GET` | `/api/users/me/stats` · `/me/dashboard` | ✅ | Статистика профиля |
| `POST` | `/api/progress/complete` | ✅ | Начисление награды за уровень (первая версия продукта) |

Роуты `/users/:id/*` были заменены на `/users/me/*`: идентификатор берётся из
токена, а не из URL, иначе любой мог подставить чужой.

### Валидация DTO
Реализован строгий **ValidationPipe** на глобальном уровне `main.ts` (`whitelist: true`, `forbidNonWhitelisted: true`). Он блокирует запросы с невалидными UUID или атаки типа *Mass Assignment* (попытка передать "hackerField" в Payload).

### Обработка ошибок (PrismaExceptionFilter)
Создан и подключен глобальный фильтр `PrismaExceptionFilter`. Он перехватывает низкоуровневые ошибки базы данных (PrismaClientKnownRequestError) и преобразует их в корректные HTTP-статусы:
- `P2002` (Unique constraint failed) -> `409 Conflict`.
- `P2025` (Record not found) -> `404 Not Found`.

## 4. Testing & Stability

- **Unit Tests (14)**: изолированные тесты `ProgressService` и `UsersService`,
  PrismaService замокан, проверяются граничные сценарии.
- **E2E Tests (10)**: эндпоинт прогрессии через `Supertest` — структура ответов,
  коды 200/400/404/409, работа валидаторов `class-validator`.
- **Чего тестами не покрыто:** весь адаптивный разговор, переспрос, потолок
  вопросов, одноразовость награды и списание очков за разбор. Всё это проверено
  вручную на живой модели, но не зафиксировано тестами — см. [PLAN.md](PLAN.md).
- **Seed Script (`prisma/seed.ts`)**: Идемпотентный скрипт наполнения базы. Каталог — 6 проработанных профессий с шаблонными уровнями и данными рынка труда РК. Статические UUID + `upsert` позволяют безопасно вызывать `npx prisma db seed` при деплое; уровни от прошлых версий каталога скрипт вычищает сам.

## 5. Адаптивный тест и слой ИИ

Главная часть продукта. У теста **нет ключа ответов**: подросток отвечает свободной
речью, а следующий вопрос рождается из предыдущего ответа. Уберите модель —
останется пустой экран.

- **Модуль `src/ai`** — клиент Claude (`@anthropic-ai/sdk`) и девять промптов:
  разбор свободного ответа, следующий вопрос, переспрос, подбор профессий,
  рабочая проба, её второй шаг, письмо родителям, разбор наставника и путь в
  профессию. Структурированные ответы идут через structured outputs + zod.
- **Разговор длится столько, сколько нужно**: от 4 до 10 вопросов. Конец
  наступает, когда модель говорит, что уже может назвать профессии и объяснить
  выбор. Пустой ответ («не знаю», «норм») она помечает `informative: false`, и
  тот же вопрос задаётся заново — проще и конкретнее, до двух раз подряд.
  Отписками тест не пройти: они не двигают счётчик содержательных ответов.
- **Класс** спрашивается перед стартом и уходит в промпты: восьмикласснику и
  выпускнику перед ЕНТ нужны разные примеры и разная сложность.
- **Рабочая проба необязательна и живёт отдельно.** Разговор заканчивается
  результатом; проба запускается кнопкой с экрана результата и состоит из двух
  шагов, где второй вырастает из принятого решения.
- **Сценарий целиком** (`src/sessions`): `POST /api/sessions` →
  `POST /api/sessions/:id/answers` (вопросы) → `GET /api/sessions/:id/result` →
  дальше по желанию: `POST /api/sessions/:id/trial` (проба),
  `POST /api/sessions/:id/plan` (ЕНТ, вузы, путь к работе),
  `GET /api/sessions/:id/parent-letter` (SSE),
  `POST /api/sessions/:id/claim` (сохранить в аккаунт и получить очки),
  `POST /api/sessions/:id/mentor-review` (разбор пробы за очки).
- **Прохождение открыто без логина** (`@Public`): жюри открывает демо по ссылке с
  телефона. За токеном — только claim и разбор наставника.
- **Очки**: 100 XP и 50 очков за разговор, ещё столько же за пробу. Тратятся
  только на разбор наставника (100 очков) — то есть без пробы на него не хватает,
  с пробой хватает ровно.
- **Требования закона РК № 230-VIII** (действует с 18.01.2026): экран согласия,
  дисклеймер и маркировка сгенерированного контента (`modelId` на каждом задании,
  `generatedByAi` в ответе API).
- **Модель зависит от языка.** Русский — `claude-haiku-4-5` (`ANTHROPIC_MODEL`),
  казахский — `claude-sonnet-5` (`ANTHROPIC_MODEL_KK`): на Haiku казахский
  получается ломаным, это проверено прогоном. Расход пишется в лог на каждом
  вызове; прохождение стоит около $0.06 на русском и $0.12 на казахском.

## 6. Deployment Readiness

1. **CORS**: разрешён в `main.ts` — фронт на Next.js (каталог [web/](web), порт 3001)
   ходит на этот API напрямую.
2. **Swagger Documentation**: интерактивная документация по пути `/api/docs`. Все
   методы и DTO аннотированы (`@ApiProperty`, `@ApiResponse`), включая примеры JSON.
3. **Environment Management**: база подключается через `DATABASE_URL`, авторизация
   зависит от `SUPABASE_JWT_SECRET`, слой ИИ — от `ANTHROPIC_API_KEY`. Все три
   переменные обязательны: без них приложение падает на старте, а не молча работает
   с дефолтом.
