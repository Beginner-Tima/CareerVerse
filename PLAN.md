# CareerVerse — состояние и план

Точка входа для следующей сессии. Обновлено 8 августа 2026 (вечер).

Связанные документы: [README.md](README.md) — архитектура бэкенда;
`CareerVerse-hackathon-research.md` (у команды) — исходный ресерч по теме,
конкурентам, казахскому языку и праву РК.

## Как устроен репозиторий

```
CareerVerse/
├── src/    prisma/   api/    Бэкенд: NestJS + Prisma + PostgreSQL
└── web/                      Фронт: Next.js + React
```

Две независимые сборки и два разных `package.json`: корневой — бэкенд, `web/` —
фронт. Общего workspace нет намеренно, деревья зависимостей не пересекаются.
На Vercel это тоже два отдельных проекта.

Сквозной сценарий прогнан в настоящем браузере против этих адресов: три
адаптивных вопроса, рабочая проба, результат и письмо стримом. Ошибок в консоли нет.

Замерено на проде: функция и база обе во Франкфурте, тёплый запрос с обращением
к базе ~0.30 с. Письмо родителям приходит 25 кусками, растянутыми на 7 секунд
(медианная пауза 265 мс) — Vercel действительно стримит, эффект печати настоящий.
Холодный старт функции добавляет 1.5–2 с к первому запросу.

## Как запустить локально

```sh
# 1. Бэкенд (порт 3000). Нужен PostgreSQL и ключ в .env
npm run build && npm run start:prod

# 2. Фронт (порт 3001)
cd web && npm run dev
```

Открыть `http://localhost:3001`. Swagger — `http://localhost:3000/api/docs`.

## Как выкатывать

```sh
vercel deploy --prod --yes            # бэкенд, из корня репозитория
cd web && vercel deploy --prod --yes  # фронт

# Каталог профессий живёт в базе, а не в коде — деплой его не обновит.
# Строку подключения к проду взять негде (см. ниже про миграции), поэтому
# расширение каталога идёт тем же путём, что и миграции. Сам SQL генерируется
# из prisma/catalog.ts, чтобы описания в коде и в базе не разъезжались:
npm run catalog:sql > prisma/catalog-expansion.sql   # если правили каталог
supabase db query --linked -f prisma/catalog-expansion.sql
supabase db query --linked 'select count(*) from "Profession"'   # ждём 102
```

**Автодеплоя по push не будет, и это не лень.** Vercel не умеет подключаться к
репозиторию, который принадлежит личному аккаунту другого человека, если у тебя
там роль Collaborator, а не владелец. `Beginner-Tima/CareerVerse` — ровно этот
случай (`push: true`, `admin: false`), поэтому деплой идёт из локальной папки.
Если автодеплой нужен — форкнуть репозиторий себе и подключить форк.

Секреты живут только в переменных окружения Vercel (`vercel env ls production`),
в репозиторий не попадают: `.env*` и `.vercel` в `.gitignore`, скан 62 файлов
перед пушем секретов не нашёл.

### Что важно знать про базу

- **Только пулер, никогда не прямое подключение.** Прямой хост
  `db.<ref>.supabase.co` живёт только по IPv6, а Vercel ходит по IPv4 — с
  прямой строкой прод просто не поднимется. Приложение работает через
  transaction mode (6543), миграции — через session mode (5432).
- **TLS настроен явно в коде.** Новый драйвер `pg` трактует `sslmode=require`
  как `verify-full`, а сертификат Supabase подписан их собственным CA, которого
  нет в системном хранилище. Корневой сертификат лежит в `SUPABASE_CA_CERT`,
  проверка включена. Без переменной приложение работает, но пишет предупреждение.
- **Миграции на прод идут не через Prisma, и это не лень.** Переменные на Vercel
  помечены как sensitive: `vercel env pull` выгружает `DATABASE_URL=""`, значение
  не отдаётся даже владельцу проекта. Строку подключения взять негде, поэтому
  `prisma migrate deploy` на прод запустить нельзя. Рабочий путь — Management API
  Supabase, где пароль не нужен:

  ```sh
  supabase link --project-ref ypgsswfqrpipawauxsbd
  supabase db query --linked -f prisma/migrations/<имя>/migration.sql

  # Prisma не узнает о применённой вручную миграции и попытается накатить её
  # снова — допишем строку сами. checksum считается по файлу миграции:
  #   shasum -a 256 prisma/migrations/<имя>/migration.sql
  supabase db query --linked "insert into _prisma_migrations
    (id, checksum, finished_at, migration_name, logs, rolled_back_at, started_at, applied_steps_count)
    values (gen_random_uuid()::text, '<checksum>', now(), '<имя>', null, null, now(), 1)"
  ```

  Проверить, что применилось: `supabase db query --linked "select migration_name
  from _prisma_migrations order by finished_at"`. Локально всё по-прежнему обычно:
  `npx prisma migrate deploy`.

### Как посмотреть, что люди отвечали

В логах ответов нет и не будет — туда пишутся только старт, ошибки API и расход
токенов. Свободному тексту живого человека не место в потоке эксплуатационных
сообщений. Всё лежит в базе:

```sh
vercel env pull .env.production.local --environment=production   # разово
env $(grep -v '^#' .env.production.local | xargs) npm run transcripts        # последние 5
env $(grep -v '^#' .env.production.local | xargs) npm run transcripts -- 20  # последние 20
```

Показывает вопрос, ответ, что из него извлекла модель, накопленный профиль и
факт письма родителям. Альтернатива без кода — SQL-редактор в дашборде Supabase.

### Предполётная проверка перед защитой

```sh
API=https://careerverse-api.vercel.app; WEB=https://careerverse-web-tau.vercel.app
curl -s -o /dev/null -w '%{http_code} фронт\n'     $WEB
curl -s -o /dev/null -w '%{http_code} каталог\n'   $API/api/professions
curl -s -o /dev/null -w '%{http_code} без токена (ждём 401)\n' \
  -X POST $API/api/progress/complete -H 'content-type: application/json' \
  --data-binary '{"levelId":"11111111-1111-4111-8111-000000000001"}'
```

Затем открыть фронт и пройти тест целиком: холодный старт функции добавляет
несколько секунд к первому запросу, поэтому один прогон «на разогрев» перед
выходом на сцену обязателен.

## Что сделано

**Ядро демо работает сквозняком и проверено на живой модели и в браузере.**

- **Схема БД.** `Session`, `TaskInstance`, `Answer`, `Assessment`,
  `InterestProfile`, `ParentLetter`, `MentorReview`, `CareerPlan`,
  `LaborMarketData`. Миграции `20260808160000_adaptive_test_core` и
  `20260808190000_accounts_adaptive_rounds_mentor` применены и локально, и на
  проде. `Level` стал шаблоном темы, а не готовым заданием.
- **Слой ИИ** ([src/ai](src/ai)) — клиент Claude и восемь промптов: разбор
  свободного ответа, следующий вопрос, переспрос, подбор профессий, рабочая
  проба, её второй шаг, письмо родителям, разбор наставника и путь в профессию.
  Structured outputs + zod, письмо идёт стримом по SSE. Модель по умолчанию —
  `claude-haiku-4-5`, прохождение ≈ **$0.06–0.12** (зависит от длины разговора).
- **Разговор адаптивной длины** ([src/sessions](src/sessions)): согласие и класс
  → от 4 до 10 вопросов → результат с рынком труда РК → путь в профессию, письмо
  родителям. Логина не требует. Сколько будет вопросов, заранее не знает никто:
  разговор кончается, когда модель говорит, что уже может назвать профессии и
  объяснить выбор.
- **Рабочая проба вынесена из теста и стала добровольной.** Матчинг всегда шёл
  по диалогу, а не по пробе, поэтому результат честен и без неё: тест стал
  короче на пару минут, а `POST /sessions/:id/trial` запускается кнопкой с
  экрана результата — когда человек уже знает, что ему подобрали, и решает,
  хочет ли попробовать эту работу руками. Проба из двух шагов, второй вырастает
  из принятого решения. На защите это два экрана вместо одного длинного.
- **Пустой ответ не проходит.** Модель помечает `informative=false`, объясняет,
  чего не хватило, и тот же вопрос задаётся заново — проще и конкретнее, до двух
  раз подряд. Отписками тест не «пройти»: они не двигают счётчик содержательных.
  Уверенность профиля называет модель, а не арифметика по числу ходов.
- **Аккаунты без почты и пароля.** Имя, класс, город и код входа вида `K7WF-3RTM`.
  Токен подписывается тем же секретом, который проверяет `SupabaseStrategy`.
  Тест проходится анонимно, аккаунт предлагается после результата:
  `POST /sessions/:id/claim` привязывает сессию задним числом и начисляет награду
  одним UPDATE с условием `userId IS NULL`.
- **Очки.** 100 XP и 50 очков за разговор плюс 50/25 за каждый шаг пробы.
  Тратятся только на разбор от наставника (100 очков) — доступ к пробам других
  профессий за очки не гейтится намеренно. Арифметика не случайна: без пробы
  очков на разбор не хватает, с пробой хватает ровно. `User.level` растёт от XP.
- **Фронт на Next.js** ([web](web)) — главное меню, шапка с выходом на главную и
  профилем, каталог профессий, история прохождений, результат по своему адресу
  `/result/<id>`, тёмная тема, мобильный вьюпорт, маркировка ИИ-контента.
- **Ожидание против результата.** Перед стартом спрашиваем «Кем ты сейчас
  думаешь стать?», на экране результата показываем рядом с подобранным. Ответ
  **намеренно не уходит на сервер** и живёт в localStorage
  ([web/app/lib/expectation.ts](web/app/lib/expectation.ts)): попади он в диалог,
  приехал бы в промпт подбора вместе с ответами, и модель просто подтвердила бы
  названную профессию — расхождение исчезло бы тихо. Четыре исхода: совпало,
  почти совпало, разошлось и «было не знаю»; блок читается в любую сторону,
  поэтому сценарий защиты на расхождении строить не нужно. Цена решения: по
  ссылке с другого устройства блока не будет.
- **Профиль интересов стал диаграммой.** ProfileBar рисует полосы, которые
  растут после каждого ответа: новая черта въезжает с нуля, знакомая доезжает до
  новой ширины. Ни одного лишнего запроса к API. Коды черт модель по-прежнему
  выдаёт по-английски (это ключ слияния сигналов) — перевод только на экране,
  незнакомый код показывается как есть.
- **План на ближайший месяц вынесен наверх.** `nextMonth` был последним блоком
  «Что дальше» — теперь идёт первым и выделен: остальное в этом экране горизонт
  в годы. Промпт получил абзац про ближнюю дистанцию и знает текущий месяц
  (школьный год — главный календарь подростка), плюс запрет выдумывать даты
  регистрации по тому же правилу, что и названия вузов.
- **Каталог — 102 профессии вместо шести.** Модель отвечает только из каталога
  (за каждым вариантом стоят проба, план и письмо родителям, и все они обязаны
  называть одну профессию), поэтому длина каталога и была потолком теста: шесть
  направлений — шесть возможных ответов, как бы глубоко ни раскрылся человек.
  Широкий каталог вынесен в [prisma/catalog.ts](prisma/catalog.ts) — право,
  финансы, IT, инженерия, медицина, образование, медиа, наука, транспорт,
  сервис и десять профессий, куда идут через колледж, а не через вуз.
  - **Цифр рынка у 96 новых профессий нет, и это решение, а не недоделка.**
    Поимённой статистики по ним в открытом виде не существует: обследование
    Бюро нацстатистики даёт укрупнённые категории работников, а не профессии,
    а открытый API вакансий hh закрыт — `/vacancies` отвечает 403 без
    зарегистрированного приложения (проверено 08.08.2026, справочник регионов
    при этом отдаётся). Доступны только медианы по 26 профобластям hh.kz;
    подставлять их каждой профессии внутри области пробовали и отказались —
    у всех айтишников выходила одна цифра, у всех медиков другая, и на экране
    это читалось как данные о профессии, хотя было данными об отрасли.
    Экран результата про отсутствие данных говорит прямо.
  - Если понадобится закрыть это по-настоящему: нужен app-токен hh (регистрация
    приложения) либо ручной сбор — реалистично 25–30 профессий, не 96.
  - **id короткие и читаемые** (`lawyer`, `chef`), а не UUID: модель обязана
    скопировать id дословно, и промах по 36 символам при сотне вариантов давал
    бы 409 в момент выдачи результата. Плюс список допустимых id уходит в
    описание поля — см. `matchSchema` и оговорку там о том, почему это
    подсказка, а не гарантия.
  - Новых промптов не потребовалось: пробу, план и письмо модель собирает из
    описания профессии.
  - **Казахские названия нуждаются в вычитке носителем** — часть терминов
    заимствования, часть переведена по словарю.
  - **Локально; на проде каталог всё ещё из шести** — см. команды выката.
- **Экран результата больше не тупик.** Любой обрыв сети давал одну попытку и
  сообщение браузера («Load failed» в Safari) без выхода. Теперь сетевые ошибки
  переводятся на человеческий (`humanError` в [web/app/lib/api.ts](web/app/lib/api.ts)),
  есть кнопка «Попробовать ещё раз» и строчка о том, что результат никуда не
  пропал. Экран вопросов был восстанавливаемым и раньше: черновик ответа при
  ошибке не стирается, кнопка снова активна.
- **Гонка XP починена и перепроверена на живом сервере:** 8 параллельных запросов
  на один уровень дают 1 успех и 7×409, начислено 200 XP вместо 1400, одна запись
  прогресса вместо семи.
- **Авторизация подключена.** `JwtAuthGuard` глобальный (`APP_GUARD`), открыто
  только явным `@Public()`. `userId` берётся из токена, IDOR-роуты `/users/:id/*`
  заменены на `/users/me/*`. Дефолтный `SUPABASE_JWT_SECRET` убран — без секрета
  приложение не стартует.
- **Требования закона РК № 230-VIII** — экран согласия, дисклеймер, маркировка
  сгенерированного контента.
- Тесты зелёные: 14 unit + 10 e2e.

## Что осталось

### Приоритет 1 — риски на защите

0. **Расшифровка прохождения больше не отдаётся наружу — но дыра закрыта не вся.**
   Поле `dialogue` убрано из `GET /api/sessions/<uuid>/result`: экран результата
   его всё равно не рисовал, наружу уходят только выводы (профиль, профессии,
   рынок), сам текст остаётся в базе. **Локально, на прод не выкачено.**
   Что осталось нерешённым: удалять прохождения по-прежнему нечем — кнопки
   «удалить мои ответы» и срока хранения нет. Если жюри спросит про
   персональные данные подростков, честный ответ теперь такой: ответы не
   утекают по ссылке, но и удалить их человек не может.

1. **Матчинг профессий недетерминирован — починено только на русском.**
   Два одинаковых прогона давали разный первый вариант (Backend 0.89 /
   Агроинженер 0.89). Для промпта подбора выставлена `temperature: 0`, но
   срабатывает она лишь на Haiku: **Sonnet 5 параметры сэмплирования не
   принимает вообще — ненулевая `temperature` возвращает 400**, поэтому на
   казахском значение молча не отправляется (`SAMPLING_SUPPORTED` в
   [src/ai/claude.service.ts](src/ai/claude.service.ts)). Казахское демо
   по-прежнему стоит прогнать заранее. Разброс на русском после правки
   не перепроверялся живым прогоном.
2. **Казахский проверен и работает — но на другой модели.** Прогон на `KK`
   сделан 08.08.2026. На Haiku 4.5 казахский оказался ломаным («Білмеймін деген
   сөйлеу нәтиже бермесе, сөндіктен ойлан да көр» — это не язык, а набор слов),
   поэтому для `KK` модель поднята до `claude-sonnet-5`
   (`ANTHROPIC_MODEL_KK` в переменных окружения). На нём язык грамотный, проба
   осмысленная, названия профессий берутся из `titleKk`.
   **Цена вопроса:** казахское прохождение до пробы включительно ≈ **$0.12**
   (замерено), с письмом и планом ближе к $0.20; русское на Haiku — около $0.06.
   Если ключ кончится на защите, `ANTHROPIC_MODEL_KK=claude-haiku-4-5` вернёт
   дешёвый вариант ценой качества языка.
3. **Латентность.** Один ответ = 2 вызова модели, 8–15 секунд. Разговор до
   результата — 4–10 вопросов, то есть 2–4 минуты; проба добавляет ещё пару, но
   уже по выбору человека. Если на сцене не влезаем, крутить здесь:
   `CLARIFYING_MIN`/`CLARIFYING_MAX` и `TRIAL_ROUNDS` в
   [src/sessions/sessions.service.ts](src/sessions/sessions.service.ts).
4. **Разбор ответа не стримится — и стримиться не будет.** Письмо родителям
   идёт потоком, потому что это проза; `assessAnswer` и все остальные вызовы
   идут через structured outputs с zod, и по каналу пошёл бы недописанный JSON,
   показывать который нечего. Вместо стрима на кнопке теперь три подписи,
   переключаемые по факту двух реальных вызовов: «Читаю ответ» → «Ищу, что за
   этим стоит» → «Придумываю следующий вопрос» (в пробе — свои три). Пауза
   осталась те же 8–15 секунд, но перестала быть пустой. Настоящий стрим
   потребовал бы лишнего вызова модели на горячем пути каждого ответа.

### Приоритет 2 — качество

5. Обрыв сессии закрыт на двух главных экранах — результат (кнопка «Попробовать
   ещё раз») и вопросы (черновик сохраняется). Остались `/trial/<id>`, `/me` и
   каталог: там ошибка по-прежнему показывается как есть и без повтора.
6. Новая логика разговора не покрыта тестами. 14 unit + 10 e2e зелёные, но
   переспрос, потолок вопросов и одноразовость награды проверены только руками на
   живой модели. Автотестов на фронте нет вообще: сравнение ожидания с
   результатом (`compareExpectation`) прогнано вручную на 17 случаях — фразы
   («хочу быть врачом» → Врач-диагност), «не знаю»/«хз», мусор в поле. Известное
   ограничение: латиница с кириллицей не сводятся, «бэкенд» и «Backend» считаются
   разными.
7. Если появится настоящий вход через Supabase Auth — переписать
   `supabase.strategy.ts`. Проекты, созданные после октября 2025 (наш в том
   числе), подписывают токены асимметрично (ES256) и отдают ключи через JWKS;
   общего HS256-секрета у них нет. Свои токены мы подписываем сами тем же
   секретом, так что это не горит.
8. Фронт ходит на API кросс-доменно. Работает и проверено, но если на сцене
   всплывут сюрпризы с CORS — можно убрать их совсем, проксируя `/api` через
   rewrite в `next.config.ts`: фронт полностью статический, прокси обслуживает
   маршрутизатор Vercel, а не функция.

### Что честно замокано

- **Данные рынка труда** — локальная выгрузка от 08.08.2026, а не живой запрос к
  `enbek.kz`. Источник и дата подписаны на экране результата.
- **Первый вопрос теста** статический: он ничего не знает о человеке, генерировать
  его нечем. Всё остальное рождается моделью.
- **Вузы в «Что дальше» модель называет по памяти.** Промпт запрещает выдумывать
  названия, на экране стоит дисклеймер «проверь на официальном сайте», но в одном
  из прогонов она уже смешала кириллицу с латиницей в названии КазНИТУ.
