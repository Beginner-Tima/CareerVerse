# CareerVerse — состояние и план

Точка входа для следующей сессии. Обновлено 8 августа 2026 (вечер).

Связанные документы: [README.md](README.md) — архитектура бэкенда;
`CareerVerse-hackathon-research.md` (у команды) — исходный ресерч по теме,
конкурентам, казахскому языку и праву РК.

## Как устроен репозиторий

```
CareerVerse/
├── src/    prisma/   api/    Бэкенд: NestJS + Prisma + PostgreSQL
└── web/                      Фронт: Next.js + React
```

Две независимые сборки и два разных `package.json`: корневой — бэкенд, `web/` —
фронт. Общего workspace нет намеренно, деревья зависимостей не пересекаются.
На Vercel это тоже два отдельных проекта.

Сквозной сценарий прогнан в настоящем браузере против этих адресов: три
адаптивных вопроса, рабочая проба, результат и письмо стримом. Ошибок в консоли нет.

Замерено на проде: функция и база обе во Франкфурте, тёплый запрос с обращением

(медианная пауза 265 мс) — Vercel действительно стримит, эффект печати настоящий.
Холодный старт функции добавляет 1.5–2 с к первому запросу.

## Как запустить локально

```sh
# 1. Бэкенд (порт 3000). Нужен PostgreSQL и ключ в .env
npm run build && npm run start:prod

# 2. Фронт (порт 3001)
cd web && npm run dev
```

Открыть `http://localhost:3001`. Swagger — `http://localhost:3000/api/docs`.

## Как выкатывать

```sh
vercel deploy --prod --yes            # бэкенд, из корня репозитория
cd web && vercel deploy --prod --yes  # фронт
```

**Автодеплоя по push не будет, и это не лень.** Vercel не умеет подключаться к
репозиторию, который принадлежит личному аккаунту другого человека, если у тебя
там роль Collaborator, а не владелец. `Beginner-Tima/CareerVerse` — ровно этот
случай (`push: true`, `admin: false`), поэтому деплой идёт из локальной папки.
Если автодеплой нужен — форкнуть репозиторий себе и подключить форк.

Секреты живут только в переменных окружения Vercel (`vercel env ls production`),
в репозиторий не попадают: `.env*` и `.vercel` в `.gitignore`, скан 62 файлов
перед пушем секретов не нашёл.

### Что важно знать про базу

- **Только пулер, никогда не прямое подключение.** Прямой хост
  `db.<ref>.supabase.co` живёт только по IPv6, а Vercel ходит по IPv4 — с
  прямой строкой прод просто не поднимется. Приложение работает через
  transaction mode (6543), миграции — через session mode (5432).
- **TLS настроен явно в коде.** Новый драйвер `pg` трактует `sslmode=require`
  как `verify-full`, а сертификат Supabase подписан их собственным CA, которого
  нет в системном хранилище. Корневой сертификат лежит в `SUPABASE_CA_CERT`,
  проверка включена. Без переменной приложение работает, но пишет предупреждение.
- **Миграции на прод:** `DATABASE_URL=<session-mode> npx prisma migrate deploy`.

### Как посмотреть, что люди отвечали

В логах ответов нет и не будет — туда пишутся только старт, ошибки API и расход
токенов. Свободному тексту живого человека не место в потоке эксплуатационных
сообщений. Всё лежит в базе:

```sh
vercel env pull .env.production.local --environment=production   # разово
env $(grep -v '^#' .env.production.local | xargs) npm run transcripts        # последние 5
env $(grep -v '^#' .env.production.local | xargs) npm run transcripts -- 20  # последние 20
```

Показывает вопрос, ответ, что из него извлекла модель, накопленный профиль и
факт письма родителям. Альтернатива без кода — SQL-редактор в дашборде Supabase.

### Предполётная проверка перед защитой

```sh
API=https://careerverse-api.vercel.app; WEB=https://careerverse-web-tau.vercel.app
curl -s -o /dev/null -w '%{http_code} фронт\n'     $WEB
curl -s -o /dev/null -w '%{http_code} каталог\n'   $API/api/professions
curl -s -o /dev/null -w '%{http_code} без токена (ждём 401)\n' \
  -X POST $API/api/progress/complete -H 'content-type: application/json' \
  --data-binary '{"levelId":"11111111-1111-4111-8111-000000000001"}'
```

Затем открыть фронт и пройти тест целиком: холодный старт функции добавляет
несколько секунд к первому запросу, поэтому один прогон «на разогрев» перед
выходом на сцену обязателен.

## Что сделано

**Ядро демо работает сквозняком и проверено на живой модели и в браузере.**

- **Схема БД.** `Session`, `TaskInstance`, `Answer`, `Assessment`,
  `InterestProfile`, `ParentLetter`, `MentorReview`, `CareerPlan`,
  `LaborMarketData`. Миграции `20260808160000_adaptive_test_core` и
  `20260808190000_accounts_adaptive_rounds_mentor` применены и локально, и на
  проде. `Level` стал шаблоном темы, а не готовым заданием.
- **Слой ИИ** ([src/ai](src/ai)) — клиент Claude и восемь промптов: разбор
  свободного ответа, следующий вопрос, переспрос, подбор профессий, рабочая
  проба, её второй шаг, письмо родителям, разбор наставника и путь в профессию.
  Structured outputs + zod, письмо идёт стримом по SSE. Модель по умолчанию —
  `claude-haiku-4-5`, прохождение ≈ **$0.06–0.12** (зависит от длины разговора).
- **Разговор адаптивной длины** ([src/sessions](src/sessions)): согласие и класс
  → от 4 до 10 вопросов → двухшаговая рабочая проба → результат с рынком труда
  РК → путь в профессию, письмо родителям, разбор наставника. Логина не требует.
  Сколько будет вопросов, заранее не знает никто: разговор кончается, когда
  модель говорит, что уже может назвать профессии и объяснить выбор.
- **Пустой ответ не проходит.** Модель помечает `informative=false`, объясняет,
  чего не хватило, и тот же вопрос задаётся заново — проще и конкретнее, до двух
  раз подряд. Отписками тест не «пройти»: они не двигают счётчик содержательных.
  Уверенность профиля называет модель, а не арифметика по числу ходов.
- **Аккаунты без почты и пароля.** Имя, класс, город и код входа вида `K7WF-3RTM`.
  Токен подписывается тем же секретом, который проверяет `SupabaseStrategy`.
  Тест проходится анонимно, аккаунт предлагается после результата:
  `POST /sessions/:id/claim` привязывает сессию задним числом и начисляет награду
  одним UPDATE с условием `userId IS NULL`.
- **Очки.** 100 XP и 50 очков за тест плюс 50/25 за каждый шаг пробы. Тратятся
  только на разбор от наставника (100 очков) — доступ к пробам других профессий
  за очки не гейтится намеренно. `User.level` растёт от XP.
- **Фронт на Next.js** ([web](web)) — главное меню, шапка с выходом на главную и
  профилем, каталог профессий, история прохождений, результат по своему адресу
  `/result/<id>`, тёмная тема, мобильный вьюпорт, маркировка ИИ-контента.
- **Каталог** — 6 проработанных профессий (Backend, Product-дизайнер,
  врач-диагност, агроинженер, учитель, логист) с данными рынка труда РК.
- **Гонка XP починена и перепроверена на живом сервере:** 8 параллельных запросов
  на один уровень дают 1 успех и 7×409, начислено 200 XP вместо 1400, одна запись
  прогресса вместо семи.
- **Авторизация подключена.** `JwtAuthGuard` глобальный (`APP_GUARD`), открыто
  только явным `@Public()`. `userId` берётся из токена, IDOR-роуты `/users/:id/*`
  заменены на `/users/me/*`. Дефолтный `SUPABASE_JWT_SECRET` убран — без секрета
  приложение не стартует.
- **Требования закона РК № 230-VIII** — экран согласия, дисклеймер, маркировка
  сгенерированного контента.
- Тесты зелёные: 14 unit + 10 e2e.

## Что осталось

### Приоритет 1 — риски на защите

0. **Расшифровка прохождения открыта по ссылке.** `GET /api/sessions/<uuid>/result`
   отдаёт поле `dialogue` без токена — проверено на проде, ответы видны целиком.
   UUID не угадывается, но это защита незнанием адреса, а не авторизацией.
   Плюс удалять прохождения нечем: согласие спрашиваем, а кнопки «удалить мои
   ответы» и срока хранения нет. Если жюри спросит про персональные данные
   подростков — честный ответ сейчас именно такой.

1. **Матчинг профессий недетерминирован.** Два одинаковых прогона дали разный
   первый вариант (Backend 0.89 / Агроинженер 0.89). Если на сцене важно
   попадание — прогнать заранее и показывать записанный сценарий, либо
   зафиксировать `temperature: 0` для промпта подбора (на Haiku параметр ещё
   доступен) и перепроверить разброс.
2. **Казахская версия не проверена.** Локаль `KK` прокинута по всему пути, но
   реальный прогон на казахском не делался — качество ответов модели неизвестно.
   74% выпускников сдают ЕНТ на казахском, вопрос жюри почти гарантирован.
3. **Латентность и её новая цена.** Один ответ = 2 вызова модели, 8–15 секунд.
   Раньше это было 3 вопроса, теперь от 4 до 10 плюс два шага пробы — прохождение
   растянулось до 5–8 минут. На сцене это много. Если не влезаем по времени,
   откат на один шаг пробы — это `TRIAL_ROUNDS = 1` в
   [src/sessions/sessions.service.ts](src/sessions/sessions.service.ts), а более
   короткий разговор — `CLARIFYING_MIN`/`CLARIFYING_MAX` рядом.
4. **Разбор ответа не стримится.** Пока модель думает, человек видит «Читаю
   ответ…» и ничего больше.

### Приоритет 2 — качество

5. Обработка обрыва сессии: если модель упала на середине, подросток видит ошибку
   и не может продолжить — нет кнопки «повторить».
6. Новая логика разговора не покрыта тестами. 14 unit + 10 e2e зелёные, но
   переспрос, потолок вопросов и одноразовость награды проверены только руками на
   живой модели.
7. Если появится настоящий вход через Supabase Auth — переписать
   `supabase.strategy.ts`. Проекты, созданные после октября 2025 (наш в том
   числе), подписывают токены асимметрично (ES256) и отдают ключи через JWKS;
   общего HS256-секрета у них нет. Свои токены мы подписываем сами тем же
   секретом, так что это не горит.
8. Фронт ходит на API кросс-доменно. Работает и проверено, но если на сцене
   всплывут сюрпризы с CORS — можно убрать их совсем, проксируя `/api` через
   rewrite в `next.config.ts`: фронт полностью статический, прокси обслуживает
   маршрутизатор Vercel, а не функция.

### Что честно замокано

- **Данные рынка труда** — локальная выгрузка от 08.08.2026, а не живой запрос к
  `enbek.kz`. Источник и дата подписаны на экране результата.
- **Первый вопрос теста** статический: он ничего не знает о человеке, генерировать
  его нечем. Всё остальное рождается моделью.
- **Вузы в «Что дальше» модель называет по памяти.** Промпт запрещает выдумывать
  названия, на экране стоит дисклеймер «проверь на официальном сайте», но в одном
  из прогонов она уже смешала кириллицу с латиницей в названии КазНИТУ.
